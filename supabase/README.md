# Общая база Маркообразные Новосибирск

Сайт остаётся статическим на GitHub Pages, а общие данные, вход администраторов
и фото хранятся в Supabase. Проект: `mdaqqkacxzmgazxtmwfv`.

## 1. Применить схему

1. Откройте [supabase.com](https://supabase.com) и проект клуба.
2. Слева выберите **SQL Editor** → **New query**.
3. Вставьте целиком файл `supabase/schema.sql`.
4. Нажмите **Run**. Должно появиться `Success. No rows returned`.

Скрипт можно запускать повторно — данные он не удаляет и разделы не перезаписывает.

Если изменения одного администратора не появляются у других без перезагрузки,
откройте **Database → Publications → supabase_realtime** и включите таблицу
`public.content`.

## 2. Создать первого администратора

1. **Authentication** → **Users** → **Add user**.
2. Укажите e-mail и пароль.
3. Включите **Auto Confirm User**, чтобы не ждать письма.
4. Откройте сайт и нажмите **«Войти как администратор»**.
5. Войдите этим e-mail. Первый вошедший автоматически становится владельцем
   в таблице `editors`.

## 3. Закрыть регистрацию

После создания администраторов:

1. **Authentication** → **Sign In / Providers** → **Email**.
2. Выключите **Allow new users to sign up**.
3. Сохраните.

Тогда новые аккаунты сможет создавать только владелец проекта через
**Authentication → Users**. Права на контент всё равно проверяются отдельно
по таблице `editors`, но закрытая регистрация убирает лишние аккаунты.

## 4. Добавить ещё администраторов

1. Создайте пользователя в **Authentication → Users** так же, как в шаге 2.
2. Выполните в SQL Editor:

```sql
insert into public.editors (email, role)
values ('friend@example.com', 'editor')
on conflict (email) do nothing;
```

После входа этот человек увидит общий контент и сможет его менять.

## 5. Что где хранится

| Что | Где |
|---|---|
| Новости, события, фотоальбомы, мерч, администраторы, партнёры | `public.content` (JSON по разделам) |
| Список редакторов | `public.editors` |
| Фотографии товаров и альбомов | Storage, публичный bucket `media` |
| Подписки на push (следующий этап) | `public.push_subscriptions` |

Контент читают все, но менять его могут только e-mail из `public.editors`.
Права проверяются на сервере через RLS, поэтому обойти их из браузера нельзя.

## 6. Важно про ключи

В `content.js` лежит **publishable key** — он публичный и предназначен для браузера.
**Secret key** и **service_role key** нельзя вставлять в сайт: они дают полный доступ
ко всей базе. Они понадобятся только внутри Supabase Edge Function на этапе push.

## 7. Резервная копия

В админ-панели есть кнопка **«Скачать копию»** — это JSON всех разделов.
Копию можно загрузить обратно через **«Загрузить копию»**. Дополнительно Supabase
делает ежедневные резервные копии базы на своём тарифе.
